# Feature Development Roadmap

## Principles

- Prefer demonstrable work over broad tool-name lists.
- Keep the public site static and low-maintenance until a specific backend need exists.
- Publish only verified information; show explicit project status.
- Build end-to-end portfolio projects in small slices and document evidence as they are completed.

## Prioritized roadmap

### P0 — Owner-verified resume content

- Confirm professional summary, skill list, role title, and profile destinations.
- Add resume download only after a public-safe PDF has been supplied and reviewed.
- Add project repository/demo links after validating their destination and access.

**Done when:** no stale or unsupported claim remains and all supplied links work.

### P1 — Automated delivery pipeline

- Create a small sample service or static app repository.
- Add CI for lint/validation and tests on pull requests.
- Build and scan a Docker image; publish it using repository-managed credentials.
- Document release, rollback, and failure behavior.

**Done when:** a clean commit passes CI and a reviewer can reproduce the build from documented steps.

### P2 — Cloud infrastructure as code

- Define a small, cost-limited AWS environment in Terraform.
- Separate configuration/state safely; use least-privilege IAM and secret-free source.
- Add validation/plan checks and teardown instructions.

**Done when:** another contributor can inspect the plan, deploy with their own credentials, and safely destroy resources.

### P3 — Kubernetes and GitOps

- Containerize an application and define Kubernetes resources/Helm chart.
- Configure Argo CD against a disposable cluster or documented local alternative.
- Add readiness/liveness checks, resource bounds, and rollback guidance.

**Done when:** changes are reconciled from Git and a tested rollback is described.

### P4 — Observability and reliability

- Collect metrics with Prometheus and visualize in Grafana.
- Add a small set of useful dashboards and actionable alert examples.
- Add structured log collection with an appropriate lightweight stack.
- Explain sample SLIs/SLOs and known limitations.

**Done when:** an operator can detect an injected failure from metrics/logs and follow a runbook.

## Feature lifecycle

For each feature: update its requirement/design, implement the smallest coherent slice, verify the testing checklist, update documentation/screenshots, and only then mark its public portfolio status complete.
