# Debugging Guide

## Blank or unstyled page

1. Serve the project over HTTP using [9.setup.md](./9.setup.md).
2. Open browser DevTools → Network and verify `index.html`, `assets/css/styles.css`, and `assets/js/main.js` return successfully.
3. Check path spelling and case; hosted Linux servers are case-sensitive.
4. Review the console for parse errors and reload without cache.

## Mobile navigation does not open

1. Confirm `#nav-toggle` and `#nav-menu` exist in `index.html`.
2. Confirm `assets/js/main.js` is loaded with `defer`.
3. Check that the button toggles `aria-expanded` and the menu receives/removes `is-open`.
4. Test narrow viewport and keyboard activation with Enter/Space.

## Layout overflow or unreadable content

1. Inspect at 360px viewport and locate the overflowing element in DevTools.
2. Check long unbroken text, fixed widths, grid minimum sizes, and external embeds.
3. Verify media queries in `assets/css/styles.css` are not overridden by later rules.
4. Check contrast and browser zoom; do not solve clipping by hiding meaningful content.

## A link or asset is broken after deployment

1. Open the destination directly and check the exact URL.
2. Confirm the destination is public and the owner intended to publish it.
3. Use relative paths for local assets; respect case-sensitive filenames.
4. Do not replace a missing real project with a generic image or fabricated case study.

## Former contact form/provider key

The new page intentionally has no form. If the old access key may have been used, revoke it with the provider and inspect Git history/provider logs. Removing the key from the current file does not invalidate old copies.

## Still stuck

Capture the viewport, browser console error, failing request URL/status, browser version, and reproduction steps. Remove tokens, personal data, and private repository details before sharing diagnostics.
