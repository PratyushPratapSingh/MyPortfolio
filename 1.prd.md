# Product Requirements Document

## Product

**DevOps Resume Portfolio** — a public, lightweight website that helps recruiters and engineering peers assess Pratyush Pratap Singh's DevOps focus, skills, and practical project work.

## Problem

The previous site functioned primarily as a personal profile. It listed skills without evidence, showed generic work images without project context, and used a contact form with an embedded provider key. This makes it difficult for a hiring reviewer to understand what the candidate can build and creates avoidable credential exposure.

## Goals

- Lead with a clear professional role and value proposition.
- Make the portfolio project- and evidence-focused, not just biographical.
- Present skill areas and distinguish verified profile-listed tools from project-roadmap technologies.
- Provide a concise, honest roadmap until projects have working repositories and demonstrable outcomes.
- Make the site responsive, accessible, fast, and simple to host as static files.
- Offer safe, working routes to the candidate's public profiles.

## Audience

- Technical recruiters and hiring managers evaluating a DevOps candidate.
- DevOps, cloud, platform, and SRE peers reviewing project decisions.
- The portfolio owner, who needs a maintainable place to add verified projects.

## User stories

1. As a recruiter, I can understand the candidate's role and focus from the opening section.
2. As a technical reviewer, I can scan relevant technologies and see which are part of the project roadmap.
3. As a visitor, I can navigate to projects, GitHub, LinkedIn, and contact without a broken form.
4. As the owner, I can add completed projects without building or operating a backend.
5. As a mobile visitor or keyboard user, I can navigate the site accessibly.

## Scope

### Included

- Single-page, responsive static portfolio.
- Introduction, About, Skills/Toolkit, Project Roadmap, Contact, and footer.
- Project concepts covering CI/CD, AWS/Terraform, Kubernetes/GitOps, and monitoring/logging.
- Accessible mobile navigation, skip link, visible focus, and reduced-motion behavior.
- Documentation for requirements, design, architecture, data/API boundaries, setup, security, integrations, QA, and debugging.

### Not included

- A login, admin panel, content management system, analytics, contact form, backend API, or database.
- Claiming planned projects are completed or asserting unverified project outcomes.
- AWS provisioning, Kubernetes cluster creation, or real pipeline deployment as part of the portfolio website.
- MCP server connection or tool execution from the public website.

## Functional requirements

- Navigation links scroll to the corresponding sections.
- Mobile navigation toggles from a button with an accurate `aria-expanded` state and closes after link selection.
- External profile links open safely with `rel="noopener noreferrer"`.
- The footer displays the current year using a small progressive JavaScript enhancement.
- Project cards visibly indicate their planned status; no placeholder images masquerade as project evidence.
- No API key or secret is shipped to the browser.

## Quality requirements

- Works as static files served from a local or static hosting server.
- Adapts at mobile, tablet, and desktop widths without horizontal overflow.
- Uses semantic headings/landmarks, readable contrast, keyboard focus, and reduced-motion support.
- Does not require a JavaScript framework, package install, account, or database.
- Core content remains useful if JavaScript is unavailable.

## Success criteria

- A first-time reviewer can identify the role, tool categories, project status, and profile links without guesswork.
- All roadmap work is labelled as planned until supported by public artifacts.
- The page and all in-scope assets load from a static web server with no broken local references.
- No secret, private phone number, or contact-provider token appears in shipped source.
- QA checklist in [14.testing-and-qa.md](./14.testing-and-qa.md) passes before publishing.

## Decisions and assumptions

- The source profile lists AWS, Kubernetes, Jenkins, Airflow, Ansible, Git, Python, and shell scripting; these should be confirmed by the owner before publishing as professional claims.
- The attached reference recommends a broad DevOps tool set. Those recommendations are a learning/project roadmap, not proof of experience.
- The original contact form contained a public client-side Web3Forms key. It has been removed from the new implementation. The owner should revoke/rotate it with the provider.
