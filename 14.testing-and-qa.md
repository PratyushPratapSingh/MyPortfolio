# Testing and QA

## Current test strategy

The site is static and has no test runner or package dependencies. QA combines static reference checks, browser checks, responsive inspection, and accessibility/security review. Do not report checks as passing unless they were run.

## Local verification

Start the site with the command in [9.setup.md](./9.setup.md), then verify:

### Content and links

- All sections appear in order and every navigation anchor reaches its section.
- Project cards show accurate status labels; verify the four repository links and the AI agent card's **In progress** status.
- LinkedIn/GitHub/LeetCode links have the intended destinations.
- LeetCode stats load, show total and difficulty counts, and refresh on demand.
- The latest LeetCode submission displays its problem link, result, and localized attempt date/time.
- LeetCode API failures show a visible fallback state with the profile link still available.
- No old form, provider key, fake project screenshot, or placeholder link is present in the active page.
- Browser console shows no local resource or JavaScript errors.

### Interaction and accessibility

- Use Tab/Shift+Tab to reach all controls and verify visible focus.
- Activate the skip link and mobile navigation using keyboard and touch.
- Check the menu button's expanded state changes when opened/closed and link selection closes it.
- Confirm headings, landmarks, image alternatives (if images are added), and link names make sense with a screen reader.
- Enable reduced motion and confirm the page remains usable.
- Check text contrast and zoom to 200% without loss of content or function.

### Responsive behavior

Inspect at approximately 360px, 768px, and 1440px viewport widths. Check for horizontal overflow, obscured headings under the sticky header, clipped cards, and awkward menu wrapping.

### Security and privacy

- Search changed/shipped files for credential-like values and private information.
- Confirm no contact form, API key, or unnecessary external script is loaded.
- Verify the LeetCode request contains only the public profile username and no visitor input.
- Check every new-tab external link for `rel="noopener noreferrer"`.
- Confirm contact actions are honest about where the user will be sent.

## Suggested command checks

Run from the repository root:

```bash
git diff --check
grep -RInE 'access_key|api[_-]?key|secret|password' --exclude-dir=.git .
```

Review matches manually: security documentation may mention credential terms, and a match is not automatically a leaked credential. The secret scan cannot erase or inspect previous commits; review history and revoke exposed credentials separately.

## Release gate

Publish only after content is owner-verified, local references work, the responsive/accessibility checklist passes, no live secret is found, and project status accurately reflects evidence.
