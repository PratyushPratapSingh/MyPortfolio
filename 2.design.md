# Design Specification

## Design intent

Present an engineering portfolio that feels like a clear technical case-study index rather than a generic personal profile. Use a dark, restrained interface, high-contrast lime accent, crisp typography, and structured cards inspired by an automated delivery workflow.

## Visual system

- **Canvas:** deep charcoal `#10171b`.
- **Surfaces:** charcoal-green `#151e22` and alternate section `#131b1f`.
- **Accent:** lime `#a9ef77` for links, emphasis, and status markers.
- **Text:** near-white `#f1f5f2`; secondary text `#a2b0ab`.
- **Borders:** muted slate `#2d3a3e`.
- **Typography:** system UI sans-serif stack; monospace only for pipeline labels and project indices.
- **Layout:** centered content column, maximum width 1120px, consistent spacing and subtle borders.

## Page structure

1. Sticky header with circular profile photo beside the brand, in-page navigation, monogram favicon, and contact call to action.
2. Hero with role, concise value statement, GitHub link, and a decorative delivery-pipeline illustration.
3. About section with a short professional summary.
4. Toolkit grouped into four categories, separating profile-listed tools from planned project technologies.
5. LeetCode progress panel with a solved total, per-difficulty counts, and the latest public attempt with its result, date/time, and problem link.
6. Project cards for four linked DevOps repositories and AI agent development, with visible status, scope, and technology tags.
7. Contact block linking to public LinkedIn and GitHub profiles.
8. Footer with name and current year.

## Responsive behavior

- **Wide desktop (>900px):** two-column hero and About; four skill cards; two project columns.
- **Tablet (641–900px):** stacked hero; two skill columns; About remains two-column when space permits.
- **Mobile (<=640px):** compact menu button, vertical menu panel, one-column cards and content, reduced horizontal padding.

## Interaction and accessibility

- Native anchor navigation with clear section IDs.
- Mobile menu button exposes `aria-expanded`, `aria-controls`, and an accessible name.
- Skip link appears on keyboard focus.
- `:focus-visible` provides a visible high-contrast outline.
- Icons and decorative marks do not carry essential meaning alone; status text is explicit.
- External links opened in a new tab use `noopener noreferrer`.
- Live LeetCode values have a visible loading/error state and manual refresh control.
- The submission date/time uses the visitor's local timezone and does not imply active problem solving.
- Respect `prefers-reduced-motion`; no scroll-reveal dependency or motion-required content.
- Use semantic header, nav, main, sections, headings, and footer.

## Content principles

- Use first-person but concise career language; avoid unsupported metrics and claims.
- Project status labels distinguish **Planned** work from **In progress** work; do not imply completion without evidence.
- Do not use the old generic stock project images as if they were real project screenshots.
- Replace draft bio, profile links, and skills only with owner-verified details.
- Avoid skill percentage bars, which imply an unverifiable proficiency scale.

## Design acceptance checklist

- No horizontal scroll at 360px, 768px, and 1440px widths.
- Text and focus are legible against their backgrounds.
- Header does not obscure in-page section headings.
- Navigation is operable by keyboard and touch.
- Cards remain understandable when stacked on narrow screens.
