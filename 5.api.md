# API

## Current API status

There is no portfolio-owned API. The site is static HTML, CSS, and JavaScript, with no fetch/XHR calls, form posts, API credentials, or backend endpoints. The current contact action links directly to LinkedIn; it does not submit or store a message.

External GitHub and LinkedIn URLs are browser navigation, not a server integration or a documented API dependency.

## If an API is introduced

Add an API only for a concrete feature that cannot be served safely as static content. Document the deployment owner, authentication model, request/response schemas, error behavior, rate limits, data retention, and monitoring before connecting it to the site.

A future contact endpoint should:

- Accept only the fields required to deliver a message.
- Validate and bound input on the server; never trust browser validation alone.
- Enforce rate limits and abuse/bot protections.
- Return explicit success/error responses without exposing internal provider details.
- Keep mail-provider keys in server-side secret storage.
- Avoid retaining message data unless required and disclosed.

Do not add a client-side secret or invent a success response when delivery fails. There is no API contract to test until a backend is actually selected and implemented.
