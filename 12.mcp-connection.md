# MCP Connection

## Current status

The portfolio has no Model Context Protocol (MCP) server or client connection. It does not need one: a public resume site is static content, and connecting external agent tools would introduce unnecessary credentials and an avoidable trust boundary.

## If MCP is needed for development

An MCP integration may be useful in a private authoring workflow—for example, retrieving approved project metadata or checking repository status—but should remain a local/development tool. It must not run in the visitor's browser or be required to render the public site.

Before connecting one:

1. Define the concrete task and minimum read/write permissions.
2. Use a trusted server and inspect its declared tools and data handling.
3. Store credentials in the local secure environment or host secret store, never in this repository.
4. Require human confirmation before publishing or changing public content.
5. Treat tool output as untrusted input; validate URLs, text, and project claims.
6. Document disablement, access revocation, and failure behavior.

## Public deployment boundary

Do not expose MCP endpoints, server credentials, filesystem tools, or unrestricted agent actions to site visitors. A browser-facing MCP feature would require a separate security design and an explicit product requirement.
