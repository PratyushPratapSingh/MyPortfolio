# Integrations

## Current links

The website links to public profiles:

- GitHub: `https://github.com/PratyushPratapSingh`
- LinkedIn: `https://www.linkedin.com/in/pratyushpratapsingh/`
- LeetCode: `https://leetcode.com/u/pratyushpratapsingh11/`

The LeetCode section fetches public solved-problem and accepted-submission counts from `https://leetcode-api-pied.vercel.app/user/pratyushpratapsingh11` and recent submissions from its `/submissions` route. It shows the newest recorded attempt with its problem link, result, and date/time in the visitor's local timezone; this does not imply the user is currently solving a problem. It makes no authenticated request, sends no visitor input, and requires no API key. Data refreshes on page load, every five minutes, or when the visitor selects **Refresh stats**. If either feed is unavailable or changes its response, the affected panel shows an explicit unavailable state while the other data and direct profile link remain available.

The browser request discloses the public LeetCode username to the community API provider. The site does not embed external widgets or send visitor-identifying input. HackerRank is not currently linked.

## Removed integration

The prior Web3Forms contact integration was removed along with its client-side access key. The current contact section links to LinkedIn and GitHub and does not promise email delivery.

The previous key should be revoked/rotated with Web3Forms. A replacement form integration must use an approved service, understand its data processing and spam controls, and avoid exposing credentials. For a provider requiring a private secret, use a server-side endpoint rather than browser JavaScript.

## Adding an integration

Before integrating a service:

- Confirm owner approval, purpose, and current destination.
- Prefer a normal link over a script, tracker, or API call when it meets the need.
- Review privacy, accessibility, availability, credential exposure, and CSP implications.
- Keep secrets out of public source and browser requests.
- Document failure behavior and validate with network inspection after deployment.
